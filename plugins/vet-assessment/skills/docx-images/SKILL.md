# Document artwork filler

A sub-skill. Another skill hands it a `.docx`; it hands back the same document with every prompt replaced by real artwork, plus a folder of the generated images.

**The placeholder is the prompt.** These documents carry a detailed instruction written on the page where the artwork belongs. That instruction is the input. It gets read, built from, and then deleted — what ships contains no prompt text anywhere.

**Two kinds, and they are built in completely different ways:**

| | Illustration | Diagram |
|---|---|---|
| What it is | Clean instructional photography | A flat labelled drawing |
| How it is made | Generated by the OpenAI image model | **Built as native Word objects** — real shapes on a drawing canvas, or a real Word table |
| Is it a picture? | Yes, a PNG | **No.** Never rasterised |
| Editing a label | Regenerate the whole image | Click it and retype |
| Cost | Per image | Nothing |

**Diagrams are never generated as images.** A generated diagram carries labels nobody can correct and spelling nobody can trust, and in an audited document that is a defect that survives to the auditor. Built natively, every box is clickable, every label is live text, the text is searchable, and a screen reader reads it. `New-DocImages.ps1` skips diagrams on purpose.

`references/prompt-rules.md` covers writing and repairing an illustration prompt. `references/diagram-specs.md` covers turning a diagram prompt into a spec.

## Before the first run

The API key is never stored in this skill. Resolve it, in order, from `-ApiKey`, `$env:OPENAI_API_KEY`, the file at `$env:OPENAI_API_KEY_FILE`, then `%USERPROFILE%\.openai-key`. If none is set, stop and ask the user for the key — do not guess, and do not write it into any file in this skill directory.

Only illustrations cost money. Before generating more than about ten, run `New-DocImages.ps1 -WhatIfCost` and tell the user the count.

**Generate at the quality the page needs, never at the maximum and then shrink.** Quality is billed per image and rises steeply from `low` to `high`. A photograph that lands 6 cm wide on a card does not need what a full-column close-up needs, and compressing a `high` image down afterwards pays for detail nobody sees. Set `QUALITY: low | medium | high` **on the entry**, in the prompt block, beside `ASPECT`. Omit it and the entry takes the file default. **Never raise the file default "to be safe"** — that bills every image in the document for the one that needed it.

## The run

```powershell
$s = "$env:USERPROFILE\.claude\skills\docx-images\scripts"
```

### 1. Scan

```powershell
& "$s\Find-DocxImagePrompts.ps1" -Path .\DOC.docx -ManifestPath .\images\manifest.json
```

Writes `manifest.json`: one entry per prompt with its kind, paragraph span, caption and alt text. Illustrations start on `pending`; diagrams start on `needs-spec`. Exit 3 means nothing was found.

**Read the manifest before doing anything else.** This is the stage that needs judgement:

- **Check every `kind`.** Detection is keyword-based and it will get some wrong. A prompt describing a labelled bar, a flowchart, a cycle, a temperature scale or a grid is a **diagram** even if the document marked it `[IMAGE:`. Correct the field — getting this wrong either burns money on a bad picture or turns a photograph into boxes.
- **Fill every empty `caption` and `alt`.** House style requires a caption or adjacent explanation and meaningful alt text on everything placed. Where the document supplied neither, write them from the prompt and the surrounding page.
- **Sanity-check the span.** If a prompt block swallowed a following body paragraph, or stopped short of its own closing bracket, fix `paraEnd` — those paragraphs get deleted.

Found nothing, but the user says there are prompts? The document marks them some other way. Add the pattern to `config/defaults.json` under `detection.open`. Do not edit the scripts.

### 2. Build the diagrams

For every entry on `needs-spec`, read the document's prompt, write a spec into the entry's `spec` field, and set `status` to `spec-ready`. Lift the labels out of the prompt **verbatim** — they are the author's words, not yours to reword. `references/diagram-specs.md` has the format and how to pick a layout.

Then look at what you built:

```powershell
& "$s\Show-DiagramPreview.ps1" -ManifestPath .\images\manifest.json -OutDir .\images\previews
```

It runs the real layout engine, reports any box that overflows the column or overlaps another, and writes a PNG to look at. Exit 5 means it found a geometry problem — usually too many boxes. Split the diagram, or switch it to a `table`. The preview PNG is a check and never goes into a document.

### 3. Generate the illustrations

```powershell
& "$s\New-DocImages.ps1" -ManifestPath .\images\manifest.json -ImageDir .\images
```

Each illustration prompt is wrapped in the house rules and sent as one image. PNGs land in `-ImageDir` next to a `.prompt.txt` recording exactly what was sent. The manifest is saved after every image, so an interrupted run resumes rather than restarts and re-bills.

Failures are recorded, not fatal. A `status` of `failed` with an HTTP 400 note means the prompt itself was refused — rewrite that entry's `prompt` and re-run; the script only retries what is still pending. Add `-Only IMG-004` to redo one, `-Force` to redo all.

### 4. Look at what came back

Read each generated PNG and check: no text or lettering anywhere, no faces, no logos, and nothing on view that contradicts the document — bare hands on ready-to-eat food in a food-safety document, jewellery, uncovered hair.

Anything wrong: sharpen that entry's `prompt`, set its `status` back to `pending`, and re-run step 3. Two regenerations is the sensible ceiling. If one still will not come back clean, say so plainly and leave the entry `failed` rather than placing a wrong picture.

### 5. Place

```powershell
& "$s\Set-DocxImages.ps1" -Path .\DOC.docx -ManifestPath .\images\manifest.json -OutPath .\out\DOC.docx
```

Each prompt block is replaced: illustrations by a centred inline picture at 85% of the column, capped at 10 cm tall; diagrams by a native canvas or table at full column width. Both get a `Figure n:` caption and alt text. The source document is not modified.

It refuses to build while any entry is unfilled, so an unresolved prompt cannot reach a shipped document. `-AllowMissing` leaves those prompts as visible text; use it only when the user has agreed to that.

### 6. Deliver

Regenerate the PDF beside the `.docx` — never leave a stale PDF next to a fresh document. Where the calling skill has its own verifier, run it: the assessment skill's `Verify-Document.ps1` handles both.

Tell the user how many illustrations were generated, how many diagrams were built natively, where the image folder is, and name anything that failed or that you had to correct.

## Doing it in one command

```powershell
& "$s\Invoke-DocxImages.ps1" -Path .\DOC.docx -OutPath .\out\DOC.docx
```

Scan, generate and place, back to back. It skips both review gates and it cannot author a diagram spec, so it works only for a document of illustrations. It stops and tells you if it finds a diagram.

## What to change, and where

Everything tunable is in `config/defaults.json` — detection patterns, the house prompt rules, the diagram palette and fonts, sizes, quality, retries and the height cap. Tune that file; the scripts read it and should not need editing.

- `scripts/Docx-ImageLib.ps1` — OpenXML helpers, dot-sourced by the rest
- `scripts/Docx-DiagramLib.ps1` — the native shape, connector and table renderer, and the layout engine
- `scripts/Find-DocxImagePrompts.ps1` — scan, read-only
- `scripts/New-DocImages.ps1` — generate illustrations
- `scripts/Show-DiagramPreview.ps1` — check a diagram spec's geometry, and draw it
- `scripts/Set-DocxImages.ps1` — place everything
- `scripts/Invoke-DocxImages.ps1` — illustrations, end to end
- `scripts/Test-Pipeline.ps1` — self-test, no API calls, run it after changing anything here
- `references/prompt-rules.md`, `references/diagram-specs.md`

## Standing rules

- **Generate at the quality the page needs, never at the maximum and then shrink** — see the costing note above. The defaults are `medium` and `jpeg` at compression 82 because an illustration lands at about 14.4 × 9.6 cm, where `1536x1024` is already ~270 dpi and `medium` is indistinguishable from `high` in print. `-WhatIfCost` prints the per-entry quality and a count by tier; read it before paying.
- **PNG only where transparency is needed.** For a photograph it is roughly ten times the bytes for no visible gain — the same figure measured 2,300 KB as a high PNG and 129 KB as a medium JPEG. Twenty-two PNGs produced a 52 MB Word file the RTO then has to store and email; the same set as JPEG produced 4.6 MB.
- **Already generated at the wrong setting? Compress locally — do not regenerate.** Re-billing to fix file size defeats the purpose.
- **A diagram is never a picture.** If you find yourself writing an image prompt for a flowchart, stop and write a spec.
- **The document's prompt is the author's instruction.** Wrap it in house rules for an illustration; translate it faithfully into a spec for a diagram. Never rewrite its subject matter. The one exception is repairing a prompt that was refused, and then say what you changed.
- **No prompt text survives into the output.** Verify it: search the finished document for `[IMAGE`, `[DIAGRAM`, `[ILLUSTRATION` and `PROMPT:` and expect zero hits.
- **Everything placed carries alt text. Instructional images also carry a caption.** A diagram's alt text must carry every label. **One carve-out: a purely DECORATIVE image** — a cover photograph on a title page, referred to nowhere and assessed from nothing — takes alt text but **no `Figure n:` caption**, because a title page is not a figure list. Leave its manifest `caption` empty and none is placed. `-NoCaption` suppresses captions document-wide; prefer the empty caption, which is per-image.
- **Keep every generated image.** The folder beside the document is part of the deliverable, and the `.prompt.txt` files are the record of what produced each one.
- **A failure stops the document, not the run.** Build everything else, then report what is missing.
